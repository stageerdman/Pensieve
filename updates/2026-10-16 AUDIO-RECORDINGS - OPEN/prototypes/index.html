Audio recordings — design prototypes

The design exploration for making audio a first-class medium in Pensieve (desktop first). Every prototype is live against the real 19-minute diarized sales call and its real transcript (206 segments, 2,390 word-timings, 2 speakers). One shared design language (_kit.css) and one shared playback/sync engine (_audio.js) run underneath them all. Open each by double-click. Use the ◐ toggle (top-right) to check light & dark. Click words in the transcript to seek; only one recording plays at a time.

Decisions — LOCKED (2026-10-16)

Owner reviewed all prototypes; these are now the build contract (design-spec.md). Prototypes 00 / 01 / 03 / 04 refined to match.

✓ #1 · Audio in a gallery → improved waveform card

A self-contained mini-player tile: waveform + functional controls underneath, plays in place. No title/icon, no “Now playing” dock. Scales with the row height like a photo. Its transcript opens only in split view.

✓ #2 · Two reader presentations

Split view is the default (transcript-icon click + ⋯). A focused reader (player docked on top, transcript below) is the second option in ⋯. Narrow windows use the reader overlay.

✓ #3 · Recording ships now, inline

Born from the /audio command; the recorder is the inline bar. Transcription engine itself comes next — the Create / Regenerate transcript trigger is always in ⋯.

✓ #4 · Speakers by weight/tone

Per-turn gutter + weight/tone only. No second hue. The summary chips (“2 speakers · CS · polished”) are removed — they don’t exist in our UI.

✓ #5 · Always polished

Show the polished transcript; no raw/polished toggle, no chip.

✓ Other

Uniform bar height for every state (the “Recording missing” bar was too tall — fixed). Split view: dropped the transcript button, added a Collapse split view button + better close. Home: duration chip; a transcribed recording’s text fills the flask like written text. Record/stop stays accent.

Underneath: the transcript sidecar schema is locked (media/<note>/<media>.mp3.transcript.json, word + segment timings + speakers) so the upcoming transcription step has a fixed target. Search folds transcript text into the note’s body index (no SQLite). Engine note: the reference word-sync uses a flat binary search that mis-highlights where diarized speakers overlap — prototype 04 fixes it via segment-aware sync; that fix gets folded into the engine at build time.
